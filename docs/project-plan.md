# 水下垃圾识别与数据管理 MVP 计划

## 1. 项目目标

围绕“水下图像增强与识别、数据管理平台建设、垃圾溯源分析、志愿者反馈语义分析”四条主线，先完成本地可运行的 `Web + 后台` MVP，打通从上传图片到 AI 分析、人工核对、可视化展示的闭环。

## 2. 一期范围

### 2.1 产品范围

- 首页：展示项目背景、挑战、核心能力、实施路线。
- 采集页：上传潜水现场图片、填写潜点信息和志愿者反馈。
- 任务历史页：查看异步任务队列、进度、失败原因、取消和重试。
- 数据看板：展示潜点分布、垃圾类别结构、时间趋势、热点区域。
- 后台页：查看垃圾身份证、人工审核 AI 识别结果。

### 2.2 AI 范围

- 图像增强：当前已选定魔搭社区 `iic/cv_nafnet_image-denoise_sidd` 作为第一阶段增强模型，先承担去噪增强角色。
- 目标检测：当前已接入魔搭社区 `CVHub520/damo_yolo_t`，以 ONNX 方式承担第一阶段检测任务；由于它基于 COCO 类别，渔网、绳索等类别暂由规则/mock 兜底。
- OCR：当前已接入 `damo/cv_resnet18_ocr-detection-db-line-level_damo` + `iic/cv_convnextTiny_ocr-recognition-general_damo`，先对整图做文字检测，再对文本行区域做识别。
- 来源推断：首版使用规则和公开环境数据的轻量推断。
- 文本语义分析：当前接入 ModelScope OpenAI 兼容接口，使用 `Qwen/Qwen3.5-397B-A17B` 对志愿者反馈做标签、摘要、风险等级和行动建议抽取。

## 3. 技术架构

### 3.1 前端

- 网页端：`Next.js + TypeScript`
- 小程序端：原生 `微信小程序`
- 功能：项目展示、采集表单、后台展示、移动端上传与复核

### 3.2 后端

- 框架：`FastAPI`
- 功能：文件上传、AI 网关、识别流水线、看板数据接口

### 3.3 存储

- 一期：本地文件目录 + SQLite (`storage/ocean.db`)
- 二期：数据库与对象存储

## 4. 核心模块

### 4.1 水下慧眼

- 输入：原始水下图片
- 输出：增强后的图片、质量评分、处理日志
- 当前增强实现：优先尝试 ModelScope 本地 SDK 调用 `iic/cv_nafnet_image-denoise_sidd`，依赖未安装时自动回退为原图复制，保证主流程不断。

### 4.2 垃圾身份证

- 输出：垃圾类别、疑似材质、OCR 线索、候选来源、人工审核状态
- 目标：实现“一图一档，一物一证”
- 当前检测实现：优先尝试 `CVHub520/damo_yolo_t` 的 ONNX 本地推理，对可映射的容器类、餐具类、电子类、纸质类垃圾输出结构化检测结果；超出 COCO 类别覆盖范围时自动回退 mock。
- 当前执行策略：检测服务支持通过 `ONNX_EXECUTION_PROVIDER` 配置 `auto/cpu/cuda/coreml`，为后续 GPU 机器部署预留加速能力。
- 当前 OCR 实现：优先尝试 `damo/cv_resnet18_ocr-detection-db-line-level_damo` 做整图文字检测，再用 `iic/cv_convnextTiny_ocr-recognition-general_damo` 对文本行区域做识别；如果整图文字检测没有结果，则回退到物体框裁剪识别。
- 当前任务编排实现：`POST /api/v1/ai/pipeline` 先创建异步任务，再由后台执行增强、检测、OCR、语义分析与入库，并可通过 `GET /api/v1/ai/pipeline/{job_id}` 轮询。
- 当前持久化实现：增强、检测、OCR、语义分析结果会写入垃圾身份证表；任务状态、重试次数、取消时间、超时时间会写入异步任务表。
- 当前缓存实现：对相同图片内容和相同业务输入会优先命中进行中任务或已完成结果，避免重复跑模型。

### 4.3 协同中枢站

- 汇总潜点、活动、图片、AI 结果、审核结果、反馈标签
- 为月报、季报、年报提供统一数据源
- 当前语义分析实现：把志愿者备注、识别类别、OCR 线索、来源提示一并送入 LLM，返回结构化标签、摘要、风险等级和行动建议；接口异常时回退规则分析。

## 5. 接口规划

- `POST /api/v1/media/upload`：上传图片
- `POST /api/v1/ai/pipeline`：创建异步 AI 流水线任务
- `GET /api/v1/ai/pipeline/{job_id}`：查询任务状态与结果
- `POST /api/v1/ai/pipeline/{job_id}/retry`：重试失败或取消的任务
- `POST /api/v1/ai/pipeline/{job_id}/cancel`：取消排队中或执行中的任务
- `GET /api/v1/ai/pipeline-jobs`：分页查询任务历史
- `GET /api/v1/dashboard/overview`：获取看板概览数据
- `GET /api/v1/health`：服务健康检查

## 6. 当前实施节奏

1. 初始化 Next.js 与 FastAPI 工程骨架。
2. 完成本地上传与模拟流水线，先跑通端到端演示。
3. 把 NAFNet 增强与 `CVHub520/damo_yolo_t` 检测跑在真实环境上，再逐步替换成更贴合水下垃圾类别的模型。
4. 把 OCR 识别和语义分析接进垃圾身份证链路，再补数据库与审核回写。
5. 增加报告导出能力，并补齐小程序端。

## 7. 当前约束

- 当前已固定 NAFNet 作为增强模型，但是否启用真实增强取决于本地是否安装 `modelscope + torch + opencv` 相关依赖。
- 当前已固定 `CVHub520/damo_yolo_t` 作为第一阶段检测模型，但其类别来自 COCO 80 类，对渔网、绳索、塑料袋等水下专用垃圾覆盖不足。
- 当前 OCR 虽然已经补上文字检测模型，但仍以通用场景为主，对水下模糊、折射、局部遮挡场景的稳定性还需要真实样本进一步验证。
- 当前语义分析依赖云端推理接口，若 API 配额、网络或返回格式不稳定，会自动回退到规则标签；当前已增加客户端超时，但仍可能成为长耗时阶段。
- `CVHub520/damo_yolo_t` 所属的 X-AnyLabeling 平台具备视频处理、批量预测和多格式导入导出等能力，但这些平台级功能尚未在当前 Ocean 项目中单独实现。
- 当前已使用本地文件与 SQLite 作为主数据落点，但尚未引入正式迁移系统。
- 任务仍为进程内后台任务，不是外部消息队列；服务进程异常退出时，执行中的任务不会自动恢复。
- 首版识别粒度先做到“检测 + 类别”，材质和品牌线索通过规则/OCR 辅助给出。
